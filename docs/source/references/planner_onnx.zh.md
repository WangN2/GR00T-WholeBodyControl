# 运动学规划器 ONNX 模型参考

本页提供**运动学规划器** ONNX 模型输入和输出的详细规范。运动学规划器是 GEAR-SONIC 系统的核心动作生成组件：给定机器人当前状态和高层导航命令，它生成一系列未来全身姿态（MuJoCo `qpos` 帧），供低层全身控制器跟踪。

ONNX 模型是**C++ 推理栈**的一部分，由部署运行时在操作期间调用。C++ 栈管理输入构建、定时和状态管理 —— 某些输入组合无效，由 C++ 层处理以确保安全操作。本页面向希望更深入理解模型接口或构建标准部署管线之外自定义集成的开发者。

```{admonition} 训练代码与技术报告
运动学规划器训练代码和技术报告即将发布。本页记录 ONNX 模型接口，用于部署集成。
```

## 概述

规划器接受**11 个输入张量**并产生**2 个输出张量**。下面列出 6 个主要输入；其余 5 个是<a href="#advanced-inputs">高级输入</a>，由 C++ 栈管理，在大多数情况下无需修改。

**主要输入：**

| 张量名称 | 形状 | 数据类型 | 默认值 |
|-------------|-------|-------|---------|
| `context_mujoco_qpos` | `[1, 4, 36]` | `float32` | 必需 |
| `target_vel` | `[1]` | `float32` | `-1.0`（使用模式默认速度） |
| `mode` | `[1]` | `int64` | 必需 |
| `movement_direction` | `[1, 3]` | `float32` | 必需 |
| `facing_direction` | `[1, 3]` | `float32` | 必需 |
| `height` | `[1]` | `float32` | `-1.0`（禁用高度控制） |

**输出：**

| 张量名称 | 形状 | 数据类型 |
|-------------|-------|-------|
| `mujoco_qpos` | `[1, N, 36]` | `float32` |
| `num_pred_frames` | 标量 | `int64` |

其中：
- **K** = `max_tokens - min_tokens + 1`（模型相关；允许的预测范围）
- **N** = 最大输出帧数（填充后）；只有前 `num_pred_frames` 帧有效

## 坐标系

模型在 **MuJoCo 的 Z 轴朝上坐标约定**下运行：

- **X** —— 向前
- **Y** —— 向左
- **Z** —— 向上

输入和输出中的所有位置和方向向量都遵循此约定。

## 输入张量

(context_mujoco_qpos)=
### `context_mujoco_qpos`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 4, 36]` |
| **数据类型** | `float32` |
| **描述** | 规划器的上下文输入，由 4 个连续的 MuJoCo `qpos` 帧组成，代表机器人的近期状态 |

这是主要的上下文输入。它以仿真帧率提供机器人最近关节配置的 4 帧。
每帧的 36 个维度是 Unitree G1（29-DOF）模型的标准 MuJoCo `qpos` 向量：

| 索引 | 字段 | 描述 |
|-------|-------|-------------|
| 0–2 | 根位置 | `(x, y, z)`，单位：米，Z 轴朝上世界坐标系 |
| 3–6 | 根四元数 | `(w, x, y, z)` 方向 —— MuJoCo 约定 |
| 7–35 | 自由度位置 | 29 个关节角度，弧度，遵循 MuJoCo 身体树顺序 |

```{admonition} 坐标系
:class: note
所有输入 —— 包括 `context_mujoco_qpos`、`movement_direction`、`facing_direction`、`specific_target_positions` 和 `specific_target_headings` —— 都应在**世界坐标系**中提供。根四元数在索引 3 到 6 处使用 MuJoCo 的 `(w, x, y, z)` 顺序。模型在内部处理规范化。
```

### `target_vel`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1]` |
| **数据类型** | `float32` |
| **描述** | 期望的运动速度覆盖 |

控制目标移动速度。当设为**零或以下**（例如 `-1.0`）时，模型使用所选模式的默认速度。当设为**正值**时，它会覆盖模式的默认速度（单位：米/秒）。注意，由于临界阻尼弹簧模型和运动动力学，实际达到的速度可能与目标不同。

| 值 | 行为 |
|-------|----------|
| `<= 0.0` | 使用所选 `mode` 的默认速度 |
| `> 0.0` | 以此目标速度覆盖（m/s） |

### `movement_direction`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 3]` |
| **数据类型** | `float32` |
| **描述** | MuJoCo 世界坐标系中期望的移动方向 |

一个 3D 方向向量 `(x, y, z)`，位于 Z 轴朝上的世界坐标系中，指示机器人应该移动到哪里。建议传递归一化向量以遵循良好实践，尽管模型在内部进行归一化。速度由 `target_vel` 和 `mode` 控制，而不是由此向量的幅度控制。

- 规划器使用 `(x, y)` 分量（水平面）通过临界阻尼弹簧模型计算目标根轨迹。
- 当幅度接近零（`< 1e-5`）时，模型回退到使用 `facing_direction`，并带有一个小的缩放因子用于原地转向。


### `facing_direction`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 3]` |
| **数据类型** | `float32` |
| **描述** | MuJoCo 世界坐标系中期望的朝向（航向）方向 |

一个 3D 方向向量 `(x, y, z)`，指示机器人躯干应该面向哪个方向。目标航向角从此向量计算为 `atan2(y, x)`。与 `movement_direction` 一样，这不需要归一化。

这与 `movement_direction` 独立 —— 机器人可以朝一个方向行走，同时面向另一个方向（例如，平移移动）。


### `height`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1]` |
| **数据类型** | `float32` |
| **描述** | 支持高度感知行为的期望根高度 |

控制支持可变高度的模式的目标骨盆高度（例如，`squat`、`kneelTwoLeg`、`kneelOneLeg`、`lyingFacedown`）。当提供正值时，模型搜索参考片段的关键帧，并选择根高度最接近请求值的关键帧，将其用作动作生成的目标姿态。

| 值 | 行为 |
|-------|----------|
| `< 0.0` | 高度控制禁用；使用从参考片段中随机选择的关键帧 |
| `>= 0.0` | 在参考片段中找到最接近高度的关键帧并将其用作目标姿态（米） |

## 高级输入

这些输入由 C++ 部署栈内部管理，在正常操作下**不应修改**。此处为完整性记录，以及需要构建自定义集成的高级用户。

### `random_seed`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1]` |
| **数据类型** | `int64` |
| **描述** | 控制网络随机性的种子 |


### `has_specific_target`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 1]` |
| **数据类型** | `int64` |
| **描述** | 标志，指示是否提供了特定航路点目标 |

| 值 | 行为 |
|-------|----------|
| `0` | 忽略 `specific_target_positions` 和 `specific_target_headings`；使用 `movement_direction` / `facing_direction` |
| `1` | 使用提供的特定目标位置和航向作为航路点约束 |

启用时，弹簧模型的目标根位置和航向会被 `specific_target_positions` 和 `specific_target_headings` 中的值覆盖。


### `specific_target_positions`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 4, 3]` |
| **数据类型** | `float32` |
| **描述** | MuJoCo 世界坐标中的 4 个航路点位置 |

每个航路点是一个 3D 位置 `(x, y, z)`，位于 Z 轴朝上世界坐标系中。4 个航路点对应 4 帧（一个 Token 的值）的目标根位置。仅在 `has_specific_target = 1` 时使用。


### `specific_target_headings`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, 4]` |
| **数据类型** | `float32` |
| **描述** | 4 个航路点航向角，弧度 |

每个航路点帧的目标航向（偏航）角。这些是 Z 轴朝上世界坐标系中的绝对角度，测量为绕 Z 轴的旋转。仅在 `has_specific_target = 1` 时使用。最后一个航路点的航向（`[:, -1]`）用作弹簧模型的主要目标航向。


### `allowed_pred_num_tokens`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, K]`，其中 `K = max_tokens - min_tokens + 1` |
| **数据类型** | `int64` |
| **描述** | 控制允许预测范围的二进制掩码 |

一个二进制掩码，其中每个元素对应一个可能的预测 Token 数。索引 `i` 映射到 `min_tokens + i` 个 Token。值为 `1` 表示允许该预测长度；`0` 表示不允许。

由于每个 Token 代表 4 帧，因此以帧为单位的预测范围是 `num_tokens * 4`。在我们的默认规划器中，`min_tokens = 6`，`max_tokens = 16`：

| 索引 | Token 数 | 帧数 |
|-------|--------|--------|
| 0 | 6 | 24 |
| 1 | 7 | 28 |
| 2 | 8 | 32 |
| 3 | 9 | 36 |
| 4 | 10 | 40 |
| 5 | 11 | 44 |
| 6 | 12 | 48 |
| 7 | 13 | 52 |
| 8 | 14 | 56 |
| 9 | 15 | 60 |
| 10 | 16 | 64 |

## 输出张量

### `mujoco_qpos`

| 属性 | 值 |
|----------|-------|
| **形状** | `[1, N, 36]` |
| **数据类型** | `float32` |
| **描述** | 预测的动作序列，以 MuJoCo `qpos` 帧表示 |

主要输出：一系列全身姿态帧，使用与输入相同的 36 维 MuJoCo `qpos` 格式（维度布局请参阅 {ref}`context_mujoco_qpos <context_mujoco_qpos>`）。

```{admonition} 重要：使用 num_pred_frames 截断
:class: warning
输出张量 `mujoco_qpos` **未被截断** —— 它包含完整的填充缓冲区。只有前 `num_pred_frames` 帧是有效的预测。消费此输出时，始终进行切片：
```

```python
valid_qpos = mujoco_qpos[:, :num_pred_frames, :]
```

姿态位于**全局 MuJoCo 世界坐标系**中（未规范化）。模型在内部处理规范化、推理和坐标转换，然后将输出转换回原始世界坐标系。前 4 个预测帧与输入上下文混合以实现平滑过渡。

输出中的根四元数使用 `(w, x, y, z)` 顺序（MuJoCo 约定）。


### `num_pred_frames`

| 属性 | 值 |
|----------|-------|
| **形状** | 标量 |
| **数据类型** | `int64` |
| **描述** | `mujoco_qpos` 输出中有效预测帧的数量 |

此值等于 `num_pred_tokens * 4`，其中 `num_pred_tokens` 是模型决定生成的动作 Token 数量（受 `allowed_pred_num_tokens` 约束）。使用此值对 `mujoco_qpos` 输出进行切片。

## 内部管线

1. **规范化** —— 输入 qpos 通过移除第一帧的航向旋转和水平位置，转换为身体相对坐标系。这有助于模型泛化到不同的起始方向和位置。

2. **弹簧模型** —— 一个临界阻尼弹簧模型从高层命令生成平滑的目标根轨迹和航向角，使用来自训练片段的模式相关平均速度。

3. **目标姿态选择** —— 基于 `mode` 和 `random_seed`，从预加载的片段库中获取目标姿态，并对齐（旋转/平移）以匹配弹簧模型预测的目标位置和航向。

4. **动作推理** —— 核心动作模型填充上下文（当前状态）和目标（期望未来状态）之间的动作，产生自然的过渡。

5. **后处理** —— 输出被转换回原始世界坐标系中的 MuJoCo qpos，前 4 帧与输入上下文混合以实现平滑过渡。

---

## 部署集成

本节描述 C++ 部署栈如何在运行时使用规划器。理解这一点对于构建自定义集成或修改重新规划行为很有用。

### 线程模型

规划器在**专用线程上以 10 Hz**（`planner_dt = 0.1s`）运行，与控制循环（50 Hz）和输入线程（100 Hz）分离。规划器线程：

1. 从线程安全缓冲区读取最新的 `MovementState`（由输入接口写入）。
2. 决定是否需要重新规划。
3. 如果是，调用 `UpdatePlanning()` 运行 TensorRT 推理。
4. 将结果存储在共享缓冲区中，控制线程在下一个节拍获取。

### 初始化

当规划器首次启用时（例如，在键盘界面上按 **ENTER**），规划器线程：

1. 从最新的 `LowState` 读取机器人当前的基座四元数和关节位置。
2. 调用 `Initialize()`，它会：
   - 在默认站立高度和零偏航方向设置 4 帧上下文。
   - 以 `IDLE` 模式和无运动运行初始推理。
   - 将 30 Hz 输出重采样到 50 Hz。
3. 控制线程检测到新的规划器动作，并将 `current_motion_` 切换到规划器输出。

### 上下文构建

规划器需要 4 帧上下文（`context_mujoco_qpos`，形状 `[1, 4, 36]`）。在操作期间，此上下文从**当前规划器动作**（而非机器人状态）采样：

- 上下文从 `gen_frame = current_frame + motion_look_ahead_steps` 开始（默认前瞻 = 50 Hz 下 2 帧）。
- 从该起点以 30 Hz 间隔采样 4 帧。
- 关节位置、身体位置和四元数在 50 Hz 动作帧之间线性插值（四元数通过 slerp），以生成 30 Hz 上下文样本。

### 重新规划逻辑

并非每个规划器节拍都会触发重新规划。决策遵循以下优先级：

**1. 始终重新规划当**（无论静态/非静态模式）：
- 移动模式改变
- 朝向方向改变
- 高度改变

**2. 对于非静态模式**，当以下任一条件为真时也重新规划：
- 移动速度改变
- 移动方向改变
- 周期性重新规划计时器到期 **且** 移动速度非零

静态模式（Idle、Squat、Kneel、Lying、Idle Boxing）**从不**触发第二类重新规划 —— 它们只在第一类中的模式/朝向/高度改变时重新规划。

**重新规划间隔**（周期性计时器）因移动类型而异，以平衡响应性和计算成本：

| 移动类型 | 重新规划间隔 |
|----------------|-----------------|
| 跑步 | 0.1 秒（每个规划器节拍） |
| 爬行 | 0.2 秒 |
| 拳击（刺拳、勾拳） | 1.0 秒 |
| 其他所有（步行、下蹲、风格等） | 1.0 秒 |

周期性计时器仅在当前移动速度非零时触发重新规划 —— 非静态模式中的静止机器人（例如，速度为 0 的 Walk 模式）不会由计时器触发重新规划。

### 输出重采样（30 Hz → 50 Hz）

规划器模型以 **30 Hz** 输出帧。部署栈使用线性插值将它们重采样到 **50 Hz**（控制循环频率）：

- 对于每个 50 Hz 帧，计算对应的分数 30 Hz 帧索引。
- 在两个最近的 30 Hz 帧之间线性插值关节位置和身体位置。
- 对四元数进行 slerp 插值。
- 通过有限差分计算重采样位置的关节速度（`(pos[t+1] - pos[t]) * 50`）。

重采样的动作存储在 `planner_motion_50hz_` 中，具有 `num_pred_frames * 50/30` 帧（向下取整）。

### 动画混合

当新的规划器输出到达而前一个仍在播放时，控制线程会在 8 帧交叉淡入淡出期间**混合**旧动画和新动画：

1. 旧动画被重新基准化，使 `current_frame` 映射到帧 0。
2. 新动画对齐到重新基准化时间线中的 `gen_frame - current_frame` 处开始。
3. 在从混合点开始的 8 帧内，应用线性增加的权重 `w_new`（0 → 1）：
   - 关节位置/速度：`w_old * old + w_new * new`
   - 身体位置：`w_old * old + w_new * new`
   - 身体四元数：`slerp(old, new, w_new)`
4. 混合区域之后，新动画完全接管。
5. 混合结果上的 `current_frame` 重置为 0。

这确保了连续规划器输出之间的平滑过渡，没有可见的不连续性。

### TensorRT 加速

规划器通过 **TensorRT** 运行，使用 CUDA 图捕获实现低延迟推理：

1. 启动时，ONNX 模型被转换为 TensorRT 引擎（缓存在磁盘上）。
2. 初始化期间捕获一个 **CUDA 图** —— 这将整个推理过程（输入拷贝 → 内核启动 → 输出拷贝）记录为单个可重放图。
3. 每次重新规划时，输入通过固定内存（`TPinnedVector`）拷贝到 GPU，启动 CUDA 图，然后拷贝回输出。
4. 通过 `--planner-precision 16` 支持 FP16 精度（默认 FP32）。

### 规划器模型版本

部署栈支持多个规划器模型版本，从模型文件名自动检测：

| 版本 | 输入数 | 模式数 | 描述 |
|---------|--------|-------|-------------|
| V0 | 6 | 4（Idle、Slow Walk、Walk、Run） | 仅基本移动 |
| V1 | 11 | 20 | 增加下蹲/跪地/拳击/风格行走 + 高度控制 + 航路点目标 |
| V2 | 11 | 27 | 所有 V1 模式 + 额外的风格行走模式 |

版本由规划器模型文件名中是否存在 `V0`、`V1` 或 `V2` 确定。版本决定：
- 输入张量的数量（6 对 11）
- `mode` 值的有效范围
- 是否使用 `height`、`has_specific_target`、`specific_target_positions`、`specific_target_headings` 和 `allowed_pred_num_tokens` 输入

## 模型属性

导出的 ONNX 模型具有以下属性：

- **ONNX opset 版本**：17
- **批大小**：1（固定）

模型以单个 `.onnx` 文件形式分发，附带一个 `.pt` 文件，其中包含可用于验证的参考输入/输出张量。

## 使用示例

```python
import onnxruntime as ort
import numpy as np

# 加载 ONNX 模型
session = ort.InferenceSession("kinematic_planner.onnx")

# 主要输入
inputs = {
    "context_mujoco_qpos": current_qpos_buffer.astype(np.float32),           # [1, 4, 36]
    "target_vel": np.array([-1.0], dtype=np.float32),                         # -1.0 = 使用模式默认速度
    "mode": np.array([2], dtype=np.int64),                                    # 2 = 步行
    "movement_direction": np.array([[1.0, 0.0, 0.0]], dtype=np.float32),      # 向前
    "facing_direction": np.array([[1.0, 0.0, 0.0]], dtype=np.float32),        # 面朝前
    "height": np.array([-1.0], dtype=np.float32),                             # -1.0 = 禁用

    # 高级输入（通常由 C++ 栈管理）
    "random_seed": np.array([1234], dtype=np.int64),
    "has_specific_target": np.array([[0]], dtype=np.int64),
    "specific_target_positions": np.zeros([1, 4, 3], dtype=np.float32),
    "specific_target_headings": np.zeros([1, 4], dtype=np.float32),
    "allowed_pred_num_tokens": np.ones([1, 11], dtype=np.int64),              # K = 11 表示默认模型
}

# 运行推理
mujoco_qpos, num_pred_frames = session.run(None, inputs)

# 仅提取有效帧
num_frames = int(num_pred_frames)
predicted_motion = mujoco_qpos[0, :num_frames, :]  # [num_frames, 36]

# 每行：[x, y, z, qw, qx, qy, qz, 29 个关节角度，弧度]
for frame in predicted_motion:
    root_pos = frame[:3]
    root_quat = frame[3:7]       # (w, x, y, z)
    joint_angles = frame[7:36]   # 29 自由度位置
```
