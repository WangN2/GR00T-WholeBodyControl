# GR00T-SONIC 训练方式与奖惩函数详解

本文档整理自 `gear_sonic/` 代码库与项目文档，涵盖训练算法、奖励函数设计及其在训练 pipeline 中的具体应用。

---

## 一、训练方式

### 1.1 核心算法：PPO + 辅助损失（Auxiliary Losses）

SONIC 采用 **PPO（Proximal Policy Optimization）** 作为基础强化学习算法，通过自定义的 `TRLAuxLossPPOTrainer` 进行训练。

| 超参数 | 默认值 | 说明 |
|--------|--------|------|
| `num_envs` | 4096 | Isaac Lab 向量化并行环境数 |
| `num_steps_per_env` | 24–32 | 每次迭代每个环境收集的步数 |
| `num_learning_epochs` | 5 | 每次数据复用 5 轮 |
| `num_mini_batches` | 4 | 每轮 PPO epoch 分成 4 个 mini-batch |
| `clip_param` | 0.2 | PPO 裁剪系数 |
| `gamma` | 0.99 | 折扣因子 |
| `lam` | 0.95 | GAE 参数 |
| `actor_learning_rate` | 2e-5 | 策略网络学习率 |
| `critic_learning_rate` | 1e-3 | 价值网络学习率 |
| `entropy_coef` | 0.01 | 熵正则系数，鼓励探索 |
| `desired_kl` | 0.01 | 自适应学习率调整的期望 KL 散度 |
| `max_grad_norm` | 1.0（release 覆盖为 0.1） | 梯度裁剪阈值 |
| `value_loss_coef` | 1.0 | 价值损失系数 |
| `aux_loss_scale` | 依配置 | 辅助损失总缩放 |

**总损失函数：**

```
总损失 = ppo_loss × ppo_loss_coef
       + value损失 × value_loss_coef
       + aux_loss_scale × Σ(coef_i × aux_loss_i)
```

### 1.2 三种训练/动作模式（Distillation 支持）

`ManagerEnvWrapper` 支持三种动作输出模式，用于教师-学生蒸馏：

| 模式 | 说明 | 应用场景 |
|------|------|----------|
| **`residual`** | 策略输出 **latent 残差**，加到 ATM 编码器输出 token 上 | **教师 RL 训练**（推荐） |
| **`direct_latent`** | 策略直接输出 **完整 latent**，绕过编码器 | **学生推理**（如视觉策略） |
| **`mixed`** | 同一 batch 内，部分环境用 residual，部分用 direct_latent | **蒸馏训练** |

### 1.3 特殊训练技术

- **对称增广（Symmetry Augmentation）**：左右镜像观测与动作，增加数据多样性。
- **图像增广 BC 损失**：视觉策略训练中，鼓励不同图像增广下动作一致。
- **域随机化（Domain Randomization）**：随机化质量、物理材质、底座 CoM、关节默认位置、随机推力扰动等。
- **自适应动作采样（Adaptive Motion Sampling）**：根据跟踪难度动态调整动作采样权重，难跟踪的动作上采样。

## 二、奖惩函数（Reward Function）

奖励函数定义于 `gear_sonic/envs/manager_env/mdp/rewards.py`，通过 Hydra YAML 配置文件组合。

### 2.1 标准奖励组合（12 项）

主配置文件：`gear_sonic/config/manager_env/rewards/tracking/base_5point_local_feet_acc.yaml`

| 奖励项 | 权重 | 参数 / 说明 |
|--------|------|-------------|
| `tracking_anchor_pos` | **+0.5** | 根位置跟踪，`std=0.3`（高斯核） |
| `tracking_anchor_ori` | **+0.5** | 根朝向跟踪，`std=0.4` |
| `tracking_relative_body_pos` | **+1.0** | 身体相对位置（5 点：root、双腕、双脚），`std=0.3` |
| `tracking_relative_body_ori` | **+1.0** | 身体相对朝向，`std=0.4` |
| `tracking_body_linvel` | **+1.0** | 身体线速度跟踪，`std=1.0` |
| `tracking_body_angvel` | **+1.0** | 身体角速度跟踪，`std=3.14` |
| `tracking_vr_5point_local` | **+2.0** | 5 点局部跟踪（躯干 + 双腕 + 双脚），`std=0.1` |
| `action_rate_l2` | **-0.1** | 惩罚动作变化率，抑制抖动 |
| `feet_acc` | **-2.5e-7** | 惩罚踝关节加速度，抑制足部抖动。release 配置覆盖为 **-2.5e-6** |
| `joint_limit` | **-10.0** | 关节越界惩罚（硬约束） |
| `undesired_contacts` | **-0.1** | 非踝/腕/肘部位触地惩罚（阈值 1.0 N） |
| `anti_shake_ang_vel` | **-0.005** | 腕部/头部角速度过大惩罚（死区 1.5 rad/s） |

### 2.2 奖励计算方式

每项跟踪奖励使用**高斯核**将误差映射到 `[0, 1]` 区间：

```
reward = exp(-error² / std²)
```

最终奖励为所有项的**加权和**：

```
R_total = Σ(weight_i × reward_i)
```

### 2.3 终止条件（Terminations）

配置文件：`gear_sonic/config/manager_env/terminations/tracking/base_adaptive_strict_ori_foot_xyz.yaml`

| 条件 | 说明 |
|------|------|
| `anchor_pos` | 根高度偏离参考运动过多 |
| `ee_body_pos` | 踝/腕高度异常 |
| `foot_pos_xyz` | 脚部位置漂移 |
| `anchor_ori_full` | 根朝向偏差 > 1 rad |
| `motion_time_out` | 片段超时结束 |

## 三、在训练中的应用流程

### 3.1 端到端训练数据流

```
运动数据预处理（CSV/BVH → motion_lib PKL，30Hz）
      ↓
环境初始化：ModularTrackingEnvCfg 组合场景、观测、奖励、终止、事件
      ↓
模型初始化：Actor（UniversalTokenModule 主干） + Critic（独立价值网络）
      ↓
Rollout 阶段：每个环境收集 num_steps_per_env 步 transitions
      ↓
GAE 计算：利用价值估计计算优势函数和回报
      ↓
PPO 更新：5 轮 epoch，mini-batch 更新策略和价值网络
      ↓
辅助损失更新（TRLAuxLossPPOTrainer）：ATM 重建损失 + 跨模态 latent 对齐损失
      ↓
日志/回调：W&B 监控、模型保存、运动评估、自适应重采样
```

### 3.2 观测空间构成

| 观测组 | 内容 | 典型维度 |
|--------|------|----------|
| **Policy (`actor_obs`)** | 本体感知 + 指令历史 + 动作历史 | ~500–1000D |
| **Critic (`critic_obs`)** | 特权信息（全身状态、未来运动参考） | 大于 actor |
| **Tokenizer** | 多模态运动输入（G1 / SMPL / Teleop / SOMA） | 变长 |
| **Vision**（可选）| RGB 图像 / 高度图 | `[H, W, 3]` |

历史帧长度：proprioception 和 action history 均为 **10 帧**。

### 3.3 Universal Token Module（ATM）在训练中的角色

SONIC 的核心是**多编码器 / 多解码器**架构：

```
          ┌─────────────┐
G1 obs    │  G1 Encoder │──┐
          └─────────────┘  │
          ┌─────────────┐  │    ┌─────────┐     ┌─────────────┐
Teleop obs│Teleop Encoder│─┼──► │   FSQ   │──►  │ G1 Dynamic  │──► 关节动作
          └─────────────┘  │    │Quantizer│     │   Decoder   │
          ┌─────────────┐  │    └─────────┘     └─────────────┘
SMPL obs  │ SMPL Encoder│──┘          │
          └─────────────┘             └──────► G1 Kinematic Decoder（仅辅助损失）
```

- **编码器**：G1、SMPL、VR Teleop（3 点）、SOMA（可选）并行编码
- **量化器**：FSQ（Finite Scalar Quantization），`fsq_level_list: [8, 8, 8, 5, 5, 5]`
- **解码器**：`g1_dyn` 用于运行时动作生成；`g1_kin` 仅用于辅助损失中的运动重建
- **编码器采样概率**：`encoder_sample_probs: [0.4, 0.3, 0.3]`（G1 / SMPL / Teleop）

### 3.4 辅助损失（Auxiliary Losses）

配置文件：`gear_sonic/config/aux_losses/universal_token/g1_recon_and_all_latent.yaml`

| 辅助损失项 | 系数 | 作用 |
|-----------|------|------|
| `g1_recon` | 0.01 | G1 运动解码器重建未来运动 |
| `g1_smpl_latent` | 1.0 | G1 与 SMPL 编码器 latent 对齐 |
| `g1_teleop_latent` | 1.0 | G1 与 Teleop 编码器 latent 对齐 |
| `teleop_smpl_latent` | 1.0 | Teleop 与 SMPL 编码器 latent 对齐 |
| `reencoded_smpl_g1_latent` | 1.0 | 循环一致性：解码后的 G1 运动重新编码回 latent |

### 3.5 关键训练监控指标

| 指标 | 收敛目标 | 说明 |
|------|----------|------|
| `rewards/total` | 3.0+ | 总奖励 |
| `rewards/anchor_pos_err` | < 0.15 m | 根位置跟踪误差 |
| `rewards/body_pos_err` | < 0.10 m | 身体位置跟踪误差 |
| `tracking_vr_5point_local` | > 0.80 | 5 点跟踪质量 |
| `time_out` | > 0.90 | 片段完成率 |
| `throughput/fps` | ~4000+ | 训练吞吐量 |

## 四、从预训练模型微调（推荐方式）

```bash
accelerate launch --num_processes=8 gear_sonic/train_agent_trl.py \
    +exp=manager/universal_token/all_modes/sonic_release \
    +checkpoint=sonic_release/last.pt \
    num_envs=4096 headless=True \
    ++manager_env.commands.motion.motion_lib_cfg.motion_file=...
```

该命令加载已发布的 `sonic_release` checkpoint，结合上述 PPO + 辅助损失 + 12 项奖励函数进行微调或继续训练。
